# 베타테스트 준비 상태

2026-11-05 기준, **공개 베타 배포 준비는 아직 완료되지 않았습니다.**
실제 Render 설정, 데이터베이스, Oracle의 기존 서비스는 변경하지 않았습니다.
GitHub에 반영하는 소스와 임시 PostgreSQL 검증 작업을 준비했습니다.
실제 업로드·검증 결과는 해당 커밋과 Actions 실행 기록을 기준으로 확인해야 합니다.

`PostgresDatabase`로 저장 모듈들을 묶었고 `create_test_server`의 `database` 인수에
명시적으로 전달하면 연결할 수 있습니다. 초기화는 미리 준비된 스키마를 조회·검증만 하며
테이블 생성이나 변경을 자동 실행하지 않습니다. 다른 학교의 기존 사용자·채널도 거절합니다.
기존 기본 실행은 여전히 PostgreSQL을 자동 선택하지 않으며 기존 Render 실행 차단은 유지했습니다.
별도 `web_service.hosted:create_hosted_app`은 명시적인 설정과 이미 준비된 전용 스키마로만
시작합니다. 설정 검사·읽기 전용 DB 검사도 준비했으며 자세한 예시는 `RENDER_BETA_DRAFT.md`에 있습니다.

베타는 앞서 정한 **5분 반복 수집 방식**을 기준으로 준비합니다. 학생별 변경 알림·구독 방식은
별도 실험 기능이며 이번 연결에서 활성화하지 않았습니다. 처리량 검사를 하기 전에는 모든 학생에게
정확히 5분 안에 결과가 보인다고 보장할 수 없습니다.

## 확인한 결과

- 마지막으로 완료된 로컬 테스트: **398개 통과, 13개 건너뜀**, 실패 없음.
- 이후 추가한 연결 설정·배포 준비·소스 패키지 검사의 로컬 실행은 자동 승인 검토에서 차단됐습니다. 이 추가분까지 로컬 테스트가 통과했다고 주장하지 않습니다.
- 개인 fork의 `oracle` 변경을 대상으로 임시 PostgreSQL 18을 띄우는 GitHub 검증 작업을 준비했습니다. 실제 DB 검사 파일별로 건너뜀 없이 실행됐는지도 확인하도록 했으며, 학교 DB나 Render 비밀값은 사용하지 않습니다. 실행 성공 여부는 Actions에서 확인해야 합니다.
- 건너뛴 검사는 별도로 지정한 일회성 PostgreSQL 테스트 DB가 필요합니다.
- 실제 SQLite 저장소와 모의 Graph 사용자 두 명을 함께 사용해 사용자별 저장과 권한 취소를 검사했습니다.
- PostgreSQL용 SQL을 SQLite로 변환하는 대체 연결을 사용해 통합 어댑터의 웹 경로도 검사했습니다. 로그인, 토큰 갱신, 일정 승인·개인 수정, 알림, 전체 로그아웃, 취소 도중 저장 거부 등이 포함됩니다. 이는 실제 PostgreSQL 실행을 대신하지 않습니다.
- 실제 PostgreSQL용 통합 검사 4개를 추가로 준비했습니다. 동시 작업 소유권, 두 학생의 공유 일정 저장, 갱신·취소 경합, 기존 데이터 보존을 검사하도록 작성했으며 현재는 건너뛴 검사에 포함됩니다.
- 실제 Microsoft Graph, 학교 로그인, Render, PostgreSQL 서버 연결 검사는 하지 않았습니다.
- 배포 패키지 검사는 이번 실행에서 제외했습니다. 기존 테스트 클라이언트의 지원 중단 예고 경고가 1개 있습니다.
- Python 수준의 외부 연결·하위 프로세스를 제한한 실행에서 차단된 호출은 0개였습니다. 이것은 운영 환경 검증이나 OS 수준 격리를 의미하지 않습니다.

## 적용 전에 설명하고 결정할 부분

1. 저장 어댑터의 실제 PostgreSQL 동시성·잠금·제약 조건을 검사하고, 배포에서 어댑터를 선택하는 설정을 마무리해야 합니다. 현재 Render 실행 차단은 유지합니다.
2. 동기화·알림 전달 스키마 초안에는 각각 `lease_token`이 추가됐습니다. 기존 DB는 초안을 다시 실행하는 것만으로 갱신되지 않습니다. 실제 DB에는 아무 변경도 적용하지 않았습니다.
3. 토큰 갱신 후 기기 버전 갱신과 전체 로그아웃 연결은 로컬 검증을 통과했습니다. 실제 DB에서의 경합·교착 상태와 학교 로그인의 종합 검사는 남아 있습니다. 이미 시작한 모든 요청·외부 알림을 로그아웃이 소급 취소하는 것은 아닙니다.
4. `requirements-postgres-experimental.txt`에 선택적인 드라이버 의존성을 기록했습니다. 현재 PC에는 바로 사용할 PostgreSQL·드라이버를 확인하지 못했습니다. GitHub의 임시 DB 검사로 실제 설치·SQL 동작을 검증하도록 준비했습니다.
5. 변경 알림 방식까지 켜려면 구독 생성·갱신·누락 복구와 PostgreSQL 학생별 작업 처리가 더 필요합니다. 이 실험 기능은 5분 수집 베타의 필수 조건으로 취급하지 않습니다.
6. 학생별 작업의 예전 실험 DB는 명시적 스키마 변경이 필요할 수 있습니다. 이 기능을 실제 서비스에 연결하거나 기존 테이블을 자동 변경하지 않았습니다.
