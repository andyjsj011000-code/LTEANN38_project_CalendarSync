새 전용 공간 최초 생성·기존 공간 보존·중간 실패 전체 취소·재시작 데이터 유지와

Render 새 웹서비스 생성 화면은 무료 요금제·Singapore·`oracle` 브랜치로 작성했습니다.

사용자가 Render 화면에 직접 입력해야 합니다. 생성한 암호화·알림 키는 소스나 ZIP에 포함하지 않습니다.

소스는 개인 fork의 `oracle` 브랜치에 반영했습니다. 최신 검사 결과는 위 GitHub 실행 기록에서 확인할 수 있습니다.

실제 Render 설정, 데이터베이스, Oracle의 기존 서비스는 변경하지 않았습니다.
GitHub에 반영하는 소스와 임시 PostgreSQL 검증 작업을 준비했습니다.
실제 업로드·검증 결과는 해당 커밋과 Actions 실행 기록을 기준으로 확인해야 합니다.

`PostgresDatabase`로 저장 모듈들을 묶었고 `create_test_server`의 `database` 인수에

테이블 생성이나 변경을 자동 실행하지 않습니다. 다른 학교의 기존 사용자·채널도 거절합니다.
기존 기본 실행은 여전히 PostgreSQL을 자동 선택하지 않으며 기존 Render 실행 차단은 유지했습니다.

정확히 5분 안에 결과가 보인다고 보장할 수 없습니다.

## 확인한 결과

- 최종 GitHub 검증: **541개 통과, 건너뜀 없음**, 기존 테스트 클라이언트 지원 중단 예고 경고 1개.
- 실제 PostgreSQL 18에서 로그인 흐름 경합·동기화 저장·큐·개인 할 일·연결 팩토리·웹 경로·스키마 초기 생성 등 **24개 통합 사례**를 별도로 다시 실행해 통과와 건너뜀 없음을 확인했습니다. 이 24개는 전체 테스트에 포함된 사례를 재검증한 수입니다.
- 앞선 로컬 실행은 자동 승인 검토에서 차단되어 재시도하지 않았습니다. 이후 검증은 GitHub의 임시 DB 환경에서 완료했으며, 학교 DB나 Render 비밀값은 사용하지 않았습니다.
- 건너뛴 검사는 별도로 지정한 일회성 PostgreSQL 테스트 DB가 필요합니다.
- 실제 SQLite 저장소와 모의 Graph 사용자 두 명을 함께 사용해 사용자별 저장과 권한 취소를 검사했습니다.
- PostgreSQL용 SQL을 SQLite로 변환하는 대체 연결을 사용해 통합 어댑터의 웹 경로도 검사했습니다. 로그인, 토큰 갱신, 일정 승인·개인 수정, 알림, 전체 로그아웃, 취소 도중 저장 거부 등이 포함됩니다. 이는 실제 PostgreSQL 실행을 대신하지 않습니다.
- 실제 PostgreSQL 연결 팩토리의 스키마·시간 제한·정상 커밋·업무 예외 및 SQL 오류 롤백도 확인했습니다. 실제 웹 API와 PostgreSQL을 함께 사용해 전체 로그아웃, 변경 승인, 알림 중복 방지, 토큰 갱신 뒤 저장, direct 공지 수집 캐시를 검사했습니다.
- 실제 학교 Microsoft 로그인·Graph·AI·외부 알림 전송과 Render의 연결 설정은 아직 검사하지 않았습니다. DB 검사는 실제 PostgreSQL이지만 외부 제공자는 모의 객체를 사용했습니다.
- 새 웹 소스 패키지 검사는 통과했고 검토용 ZIP도 생성했습니다. 예전 합성 계정용 데스크톱 실행기 패키지 검사는 별개로 제외했습니다.
- Python 수준의 외부 연결·하위 프로세스를 제한한 실행에서 차단된 호출은 0개였습니다. 이것은 운영 환경 검증이나 OS 수준 격리를 의미하지 않습니다.

## 적용 전에 설명하고 결정할 부분

1. 실제 PostgreSQL의 저장·경합·전용 공간 초기화 검사는 통과했습니다. 실제 Render의 접속·TLS·배포와 부하 검사는 남아 있습니다. 기존 기본 서버의 실행 차단은 유지합니다.
2. 동기화·알림 전달 스키마 초안에는 각각 `lease_token`이 추가됐습니다. 기존 DB는 초안을 다시 실행하는 것만으로 갱신되지 않습니다. 실제 DB에는 아무 변경도 적용하지 않았습니다.
3. 토큰 갱신 후 기기 버전 갱신과 전체 로그아웃 연결은 실제 PostgreSQL 웹 경로 검사도 통과했습니다. 실제 학교 로그인과 대규모 동시성·교착 상태 운영 대책은 추가 확인이 필요합니다. 이미 시작한 모든 요청·외부 알림을 로그아웃이 소급 취소하는 것은 아닙니다.
4. 드라이버 의존성 설치는 GitHub 환경에서 통과했습니다. 현재 PC에는 별도 PostgreSQL을 설치하지 않았습니다.
5. 변경 알림 방식까지 켜려면 구독 생성·갱신·누락 복구와 PostgreSQL 학생별 작업 처리가 더 필요합니다. 이 실험 기능은 5분 수집 베타의 필수 조건으로 취급하지 않습니다.
6. 학생별 작업의 예전 실험 DB는 명시적 스키마 변경이 필요할 수 있습니다. 이 기능을 실제 서비스에 연결하거나 기존 테이블을 자동 변경하지 않았습니다.
